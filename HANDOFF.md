# Session handoff — Blueprint fork

Development-only file; strip before any upstream PR.

## What this fork is for

Adding features to Blueprint (imbue-ai/blueprint) and dogfooding them while
developing. The owner works from iPhone and Mac via Claude Code on the web.

## Branch map

- `claude/repo-overview-kxx1m3` — dev/dogfooding branch (this one). Contains:
  - `.claude/skills/{blueprint,blueprint-generate}` — symlinks to `skills/*`
    so sessions on this branch load the skills as project skills and edits to
    `skills/` are dogfooded live.
  - `INCOMING/ams-trio-main/` — vendored reference copy of
    github.com/cellear/ams-trio (Express + Claude Agent SDK + SSE chat UI).
    Vendored because remote sessions couldn't add the repo as a source.
  - `blueprint/blueprint-web-ui/plan-blueprint-web-ui.md` — the plan for the
    next feature (see below).
- `one-question-at-a-time` — clean PR branch: only the Q&A rework on top of
  `main`. Submitted upstream to imbue-ai/blueprint (July 2026). If reviewers
  request changes, edit HERE and force-push; the dev branch carries the same
  change and should be kept in sync manually.
- `ams-trio` — owner's vendoring branch for the reference clone; untouched.

## Work completed

1. **Q&A rework** (shipped as upstream PR): the blueprint skill now asks one
   question per message (sequential numbering, bare-letter answers), every
   question carries a `skip`/`done` hint, and a one-line detail check after
   each answer reports coverage against the template sections. Files:
   `skills/blueprint/SKILL.md`, `skills/blueprint/references/questions.md`,
   `README.md`. The refinement-phase question list in blueprint-generate was
   intentionally left batched.
2. **Web UI plan** (generated by dogfooding the reworked skill end-to-end):
   `blueprint/blueprint-web-ui/plan-blueprint-web-ui.md`. Headline decisions:
   single neutral avatar, full lifecycle in browser, fully structured
   agent↔UI protocol via custom SDK tools, workspace layout where chat never
   repeats state, launched by a `/blueprint-ui` companion skill, auto-resume
   per project. Open questions are listed in the plan (testing depth is the
   big unanswered one).

## Next step

Phase 1 of the web UI plan: ams-trio-style chat-parity server (Express +
Agent SDK session loaded with the blueprint skill as system prompt), manual
launch, plain chat panel. Reference implementation patterns are all in
`INCOMING/ams-trio-main/` (see `server.js`, `lib/sessions.js`,
`public/app.js`).

## Environment notes

- Remote sessions here are non-interactive for MCP approvals: `add_repo`
  fails, and interactive pickers (AskUserQuestion) don't render — ask
  questions as plain markdown instead.
- A stop hook requires all changes committed and pushed before ending a turn.
- GitHub scope is cellear/blueprint only; upstream PR interactions
  (imbue-ai/blueprint) must be done by the owner in a browser.
- The owner's personal skills (e.g. /handoff) live on their Mac, not in this
  container.
